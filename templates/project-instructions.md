# Personal research project instructions template

Adapt this template to the actual task and merge it into an instruction file the target agent reads. Preserve existing rules. Keep unknown information unconfirmed.

- Research question, current stage, and next deliverable: confirm with the user.
- For continuation, read the existing research index and selected note first. Resume the current question from established evidence and unresolved issues; ask only for missing information that changes the next action. Keep AI-draft, user-confirmed reading, deferred implementation, and actual project-validation states distinct.
- Conversation language, explanation depth, and existing tools: use the user's established preferences. Deliverable language follows the target requirements. English source instructions do not force English conversation.
- Check materials and sources. Separate source facts, interpretation, assumptions, unverified claims, and actual results. State abstract-only access explicitly.
- Answer first, then give evidence. Use familiar words, explicit subjects, consistent terminology, and connected short sentences. Explain unfamiliar terms and retain causes, conditions, and essential derivations.
- Choose text, diagrams, tables, interactive examples, or dynamic explanations for the task. Preserve formulas, units, citations, and claim strength. Label illustrative data separately from observations.
- Merge useful understanding, corrections, and questions into existing notes after substantive discussion. Preserve human writing; avoid accumulating repeated question-and-answer logs.
- For a paper overview, identify the problem, core idea, contribution, decisive evidence, and boundaries. Answer local questions from the relevant source without requiring a whole-paper note. Deepen mechanisms, derivations, or implementation only as the question requires. Respect the user's decision to move on and retain deferred details.
- Use the agreed locations for notes, code/data, and manuscripts. Link original papers from the reference manager rather than duplicating them by default.
- For academic drafting and revision, use Anti Defensive Writing when available: lead with supported contributions, remove redundant defensive framing, preserve material unfavorable findings and evaluation conditions, and keep necessary qualifications beside the claims they constrain. Follow the requested revision scope.
- When text-watermark rewriting is requested, use the current conversation model through research-watermarks. No separate API, key, model choice or local service is required. Preserve the original and compare factual meaning and protected spans. Use standalone API automation only when explicitly requested. Keep detector verification separate from rewriting.
- Record versions, parameters, inputs, and outputs for calculations. Compare methods under compatible conditions and metrics. Say when execution has not occurred.
- Name the comparator and identify complete-method comparisons, ablations, condition contrasts, or functional coverage. Preserve differences in assumptions and metrics; feature coverage alone does not establish superiority.
- For procedures, provide prerequisites, actions, success indicators, and the next step after failure.
- Separate school or team requirements from AI suggestions. Follow authorization for sharing, spending, deleting, and overwriting.
- Check evidence and clarity before delivery. Without user feedback, do not claim the user understands.

These rules borrow ASD-STE100 principles without claiming compliance. See the [complete guide](../SETUP.md). When adapting this template into a personal project, include the necessary rule text and remove repository links that will not work there, so later sessions remain self-contained.
